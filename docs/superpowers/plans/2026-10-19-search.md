# Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Paths:** core is `crates/postvak-core/src/`, the GUI `crates/postvak-gui/src/`, MCP `crates/postvak-mcp/src/`; the binary's `src/main.rs` and `src/cli/` and the black-box `tests/` are at the root. Migrations are `crates/postvak-core/migrations/`. Read the spec first.

**Goal:** Every message's body is searchable locally, built by the daemon in the account's idle time; a typo, a prefix or a missing accent still finds the message; `from:acme after:2026-01 invoice` means the same on the CLI, over MCP and in the window.

**Architecture:** FTS5 stays the engine. A new `search` module in `postvak-core` is the only code that builds FTS expressions: `parse` turns user text into a `Query` that cannot fail, `plan` turns a `Query` into an exact FTS expression, an optional close-match expression (vocabulary terms within edit distance, read from `fts5vocab`) and SQL predicates. The account sync thread indexes the text parts of unindexed messages in five-second slices between short IDLE waits, fetching `BODYSTRUCTURE` and the text parts only, never `raw`. Front ends change only in what they pass and show.

**Tech Stack:** Rust 2024, rusqlite 0.40 (bundled SQLite with FTS5 and `fts5vocab`), async-imap 0.12 + imap-proto 0.17 (`BODYSTRUCTURE`), mail-parser 0.11, **strsim 0.11 (new direct dependency, already in the lock through clap)**, proptest 1.11, Slint 1.18.

**Spec:** `docs/superpowers/specs/2026-10-18-search-design.md`

## Decisions (settled with the owner on 2026-10-19)

1. FTS5, not tantivy. Fuzzy matching is vocabulary expansion over `fts5vocab`, not spellfix1 and not trigram.
2. Two tiers, newest first: exact, then close. The close tier runs only when exact returns fewer than ten hits.
3. The indexer fetches text parts chosen from `BODYSTRUCTURE`, plus attachment names; whole-message fallback up to 2 MB; never writes `raw`.
4. One connection per account; slices of at most 5 s, an INBOX `EXISTS` check, then a 1 s IDLE. Account idle, not machine idle. Everything is indexed, no age bound; `index_bodies = false` turns it off.
5. The auto-started daemon exits as today. Indexing advances while a client is connected or with the service installed; the docs say so.
6. Raw FTS5 syntax and `--bodies` go. Both PRs that remove them carry the `!` marker.
7. The one FTS rebuild runs inside migration 011, budget 5 s at 100k messages, measured before PR 1 merges.
8. Results stay flat messages. Substring matching inside words, relevance ordering, attachment contents and thread grouping are out of scope.
9. Dovecot is what the live tests run against; other hosts are compiled for, not run against.

## Scope

Five PRs. 2 and 3 are independent of each other and both depend on 1; 4 depends on 3; 5 depends on 2 and 3.

- **PR 1, Tasks 1–4** (`feat/search-index`): migration 011, the `search` module with words and phrases, prefix on the last word, `Store::search(&Query, Scope, limit)`, every surface on the new API. Breaks FTS5 syntax.
- **PR 2, Tasks 5–9** (`feat/search-indexer`): `BODYSTRUCTURE` and part fetches, text extraction, the slice loop, status, config, `--bodies` removed, `search.md`. Breaks `--bodies`.
- **PR 3, Tasks 10–12** (`feat/search-close`): vocabulary, expansion, tiers, `match` on every surface, `--exact`.
- **PR 4, Tasks 13–14** (`feat/search-operators`): the operator set.
- **PR 5, Tasks 15–16** (`feat/search-snippets`): snippets.

## Global Constraints

- `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test`, `cargo machete` and `cargo deny check` pass before each PR.
- No `unwrap`, `expect`, `panic!`, `unreachable!`, `todo!` or `unimplemented!` outside tests; a narrow `#[allow]` with a reason where a call cannot fail.
- User text reaches SQLite only as bound parameters or as FTS5 quoted strings built by `search::plan`. `tests/architecture.rs` enforces that no file but `store.rs` and `search/*` contains `MATCH ?` or builds an FTS expression (Task 2).
- Queries are never logged. Bodies and secrets are never logged. Snippets are body text.
- The indexer writes `body_text`, `attachment_names` and `indexed_at`, never `raw`.
- `body_text`: `NULL` means not indexed or failed; `""` means indexed with no text (headers only). `raw` alone decides whether the reader needs a fetch (`Client::raw_message` already does).
- After CLI flag or help changes: `POSTVAK_BLESS=1 cargo test`, commit `docs/src/cli.md`. After GUI work: `TZ=UTC UPDATE_SNAPSHOTS=1 cargo test -p postvak-gui snapshots`, look at the PNGs, commit them.

```rust
    pub close: Option<String>,    // PR 3
    pub sql: Vec<String>,         // PR 4; each is a predicate like "m.internaldate >= ?"
```

- [ ] **Step 2: `parse`** (`search/parse.rs`): split on whitespace outside double quotes; a `"…"` run is a `Phrase` (an unclosed quote runs to the end: `"status update` is the phrase); a leading `-` on a word or phrase makes `Not`; a lone `-` and an empty phrase are dropped; a word that is only punctuation is dropped. Everything else is a `Word`, including `from:acme` until PR 4. Tests, table-driven: `invoice` → one word; `"status update"` → phrase; `-newsletter` → not; `"unbalanced` → phrase `unbalanced`; `""` and `   ` → empty query; `re: lunch` → words `re:` and `lunch`; `"a" -"b c" d` → three terms.
- [ ] **Step 3: `plan`** (`search/plan.rs`): `pub fn plan(query: &Query, scope: Scope) -> Plan` (its signature grows in PR 3 and 4).
  - A `Word` becomes `"word"` with inner `"` doubled; the last positive term of the query, when it is a `Word`, becomes `"word" *` (FTS5 prefix). A `Phrase` becomes `"a b c"`. `Not(t)` becomes `NOT t`, and since FTS5's `NOT` is binary, positives are joined with `AND` first and negatives appended: `("a" AND "b" *) NOT "c" NOT "d"`. A query with only negatives yields an empty `exact`, which the store treats as no results.
  - `Scope::Headers` wraps the whole expression: `{subject from_addr to_addr cc_addr delivered_to attachment_names} : (…)`.
  - Tests: prefix only on the last word, not on a phrase and not on a negated word; quoting of `x") OR body_text:secret` keeps it one phrase; the headers wrapper; empty query → empty `exact`.
- [ ] **Step 4: Fuzz.** In `crates/postvak-core/tests/fuzz.rs`, a property over arbitrary strings: `parse` then `plan` under both scopes, then run the plan against an in-memory store with three messages; the only assertion is no panic and no `Err` from SQLite (an `Err` here means an expression FTS5 rejected, which `plan` must never produce). pub(crate) const INTER_SLICE_IDLE: Duration = Duration::from_secs(1);
```rust
pub(crate) const FALLBACK_RAW_LIMIT: u32 = 2 * 1024 * 1024;
const SLICE_CANDIDATES: u32 = 200;   // rows read per slice; the budget usually ends it first

pub(crate) enum SliceOutcome { Progressed, Done }

/// Indexes the newest unindexed messages for at most `SLICE_BUDGET`, one folder select at a time.
```

```rust
    if !index_checked { state.store.check_search_index().or_else(|_| state.store.rebuild_search_index())?; index_checked = true; }
    match index::slice(ops.as_mut(), &state.store, &account.name, events, &mut elapsed)? {
        SliceOutcome::Progressed => {
            // Mail that arrived while another folder was selected: EXISTS against the stored count.
            let info = ops.select("INBOX")?;
            if u64::from(info.exists) != state.store.folder_count("INBOX")? { (full, pass) = (false, true); continue; }
            match ops.idle(INTER_SLICE_IDLE, wake)? {
                IdleOutcome::NewMail => (full, pass) = (false, true),
                IdleOutcome::Timeout => (full, pass) = (now() >= next_full, now() >= next_full),
                IdleOutcome::Interrupted if shutdown.load(Ordering::Acquire) => return Ok(()),
                IdleOutcome::Interrupted => { wake.swap(false, Ordering::AcqRel); (full, pass) = (full, false) }
            }
            continue;
        }
        SliceOutcome::Done => {}
    }
}
```

  `next_full` is `last_full_pass + interval`, set after every full pass; the existing long IDLE's `Timeout → (true, true)` keeps setting it. The `check_search_index` failure path: if the rebuild also fails, send `Event::Error { message: "search index broken" }` once and set a `skip_indexing` flag for the session. Rule-pass body fetches (`MAX_RULE_BODY`) are untouched.
