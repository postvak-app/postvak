# Slint GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the egui GUI with a Slint GUI that does everything the egui one does (parity checklist), plus a native menu bar, context menus, a tray icon with close-to-background, a software-renderer fallback, an About dialog with the Slint attribution, and snapshot tests from Slint's software renderer.

**Architecture:** `gui/state.rs` is today's `App` without egui and the only code that changes state. `.slint` files under `gui/ui/` draw; `gui/bind.rs` pushes state into Slint and turns callbacks into `UiAction`s. Toolkit-free modules (list, folders, body, status, rules, html, numbers, startup) keep their logic and tests. Tests drive `App` directly, or the real window under Slint's testing backend.

**Tech Stack:** Rust 2024 (1.99), Slint 1.18.1 (`slint`, `slint-build`, `i-slint-backend-testing`), Blitz `=0.3.0-beta.2` unchanged.

**Spec:** `docs/superpowers/specs/2026-10-13-postvak-slint-gui-design.md`; parity: `docs/superpowers/specs/2026-10-13-postvak-slint-gui-parity.md`.

## Scope

One branch, `feat/slint-gui` off `origin/main`, a draft PR from the start so CI runs, merged when every parity item is ticked. Each task is one commit (or a few) that builds and passes `cargo test --all-features`.

## Global Constraints

- The AGENTS.md definition of done, at every commit: fmt, clippy `--all-targets --all-features -D warnings`, `cargo test`, `cargo machete`, `cargo audit`; `cargo check --no-default-features`.
- No `unwrap`/`expect`/`panic!` outside tests; Slint's generated code lives in `gui::ui` with those lints allowed.
- Every size comes from the theme globals (`ROW`, `CONTROL`, `INSET`, `PAD`, `ICON`, `GLYPH`, `RADIUS`, `TOP_BAR`, `LIST_ROW`), never a literal.
- Every user-visible string keeps today's wording (parity checklist), unless the design names a change.
- Never read bodies from a real store; tests use `Fixture`.
- Report "compiled on" vs "ran on" honestly; the window is checked by hand on KDE Wayland after each view task.
